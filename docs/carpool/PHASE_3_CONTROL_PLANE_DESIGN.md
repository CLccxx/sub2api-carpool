# 阶段 3：主站统一控制台与节点管理设计

日期：2026-09-19（Asia/Shanghai）

状态：用户已确认本设计；3A、3B、3C 已完成本地开发与验收，逐项核对和验证限制见 `PHASE_3_RESULTS.md`。本文保留设计契约，不代替结果报告，不代表生产上线或阶段 4 开通。未创建或使用真实节点凭证。

## 1. 范围与方案选择

用户在 A 使用现有邮箱验证码注册及账号密码登录，管理员核实站外收款后加入车辆。服务开通后，用户仍在 A 管理该车的 API Key、复制对应 API 地址及查看本人用量。不要求成员绑定 OIDC 身份或登录 B，不复制密码、密码散列、TOTP、浏览器会话或 A 的 JWT 签名密钥到 B。

| 方案 | 取舍 | 决策 |
| --- | --- | --- |
| 用户经 OIDC 跳转 B 控制台 | 已有阶段 0 基础，但成员需要统一身份及跨站页面 | 不作为首版用户路径；保留原模式和回归，不直接删除 |
| A 后端复用 B 管理 API，补少量专用接口 | 复用用量和管理能力；需要安全保管高权限 Key、可靠映射及补齐密钥操作 | 用户选择的首版方向 |
| 全部改用专门限权的节点 API | 可由 B 限制凭证作用域，但改动范围更大 | 后续加固；首版不得声称已有此凭证隔离 |

本阶段不做：任意 B 设置的远程编辑器、通用 HTTP 代理、自动采购部署、在线支付、跨车钱包、统一跨车 Key、模型流量经过 A、自动转到其他车辆、完整日志或对话内容汇集。

### 请求边界

```text
注册、车辆、密钥操作、用量页面：浏览器 -> A -> 指定节点的管理 API
模型请求：模型客户端 -> 对应车辆的 B/C 节点 -> 该节点上游
```

用户无需理解 A/B 架构，但每辆车仍有独立 API 地址。模型调用不经过 A；管理数据和向用户展示的 Key 会经过 A，不能称 A 完全接触不到敏感数据。B/C 数据库、缓存、JWT 密钥、管理员 Key 和上游凭证保持独立。

## 2. 现有能力与必须补充的部分

以下结论来自当前本地代码，不代表任意上游版本都具有相同接口：

| 能力 | 当前入口 | 使用方式 |
| --- | --- | --- |
| B 管理员 Key 验证 | `internal/server/middleware/admin_auth.go`，`x-api-key` | A 后端调用；不能使用 A 自己的 Key 代替 |
| 指定用户已有 Key | `GET /api/v1/admin/users/:id/api-keys` | A 固定映射后的用户编号，过滤返回字段 |
| 用户用量统计、明细 | `GET /api/v1/admin/users/:id/usage`、`GET /api/v1/admin/usage` | A 强制本人过滤和分页；不提供无用户范围的转发 |
| 普通站点设置管理 | `GET/PUT /api/v1/admin/settings` | 已存在，但不开放给成员，也不纳入本期远程编辑 |
| 普通用户 Key 创建/修改/删除 | `internal/handler/api_key_handler.go`、`APIKeyService` | 现有入口依赖节点登录身份；专用委托接口复用服务层，不伪造用户 JWT |
| 节点登记 | `CarpoolHandler.RegisterNode`、`MainService.RegisterNode` | 已有节点/车辆/主机名记录；新增连接配置和验证状态 |
| 节点门禁 | `internal/carpool/gate.go` | 保留旧 OIDC 分支；增加明确独立的 managed 分支 |

两项复用限制：

- `admin_user.go` 的普通创建流程会接受密码、套用默认余额并分配默认订阅。节点内部成员不能直接按此流程创建，必须有隔离的成员预配命令；不修改其他管理员创建用户的既有行为。
- `APIKeyService.Create` 会检查节点权限及分组权限；专用接口必须保留这些校验。普通幂等协调器可能保存响应正文，不能在 A 直接套用它持久化含明文 Key 的响应。

管理员 Key 仍受合规及部分敏感操作二次验证限制。不自动接受声明、不关闭二次验证、不通过服务端模拟真人登录绕过限制。正常业务缺能力时明确报告不兼容或补受审查的专用接口。

## 3. 节点连接与凭证

### A 的连接记录

沿用 `carpool_nodes` 的一车一节点关系，增加关联连接记录，保存固定管理 origin、预期节点实例编号、协议版本、凭证密文、凭证代次、连接验证结果和最近错误分类。连接状态为 `unverified / ready / error / disabled`，独立于车辆与成员状态。

- B 上生成管理员 Key，在 A 新增的「节点连接」中录入；不是写入 A 自身的管理员 Key 设置。
- 管理凭证写入后 API 只返回已配置状态及掩码，不再回显；不进入公开设置、HTML 注入、浏览器存储、URL、错误详情或审计正文。
- 使用独立的 32 字节部署加密主密钥，不共享 JWT 密钥，不依赖每次启动生成的 TOTP 密钥。缺失主密钥或解密失败则拒绝节点操作，不降级明文保存。密文使用 AES-GCM，并绑定主站、节点及凭证代次，防止跨节点误用。
- 管理员手工在 B 轮换 Key 后，在 A 替换并重验；不自动重置 B 的全局 Key。旧请求返回不得覆盖新代次的状态。
- 一辆车的连接 host、节点实例身份不允许随意改为另一台服务器；有映射/密钥后换机属于独立迁移流程。IP 变化可在同一已验证域名和身份下复验，不能把旧用户编号应用到新数据库。

全局管理员 Key 是高权限凭证。A 的代码白名单不能改变其在 B 的权限；A 被攻破时，相应 B 也面临管理员级风险。节点连接接口需要主站管理员鉴权、审计、现有二次验证策略、HTTPS 和部署层访问限制。此风险是正式上线评审项，不以「密文入库」代替完整权限控制。

### 网络边界

生产管理地址只接受配置允许的 HTTPS host/port origin，不接受路径、userinfo、query、fragment 或客户端指定的请求 URL。主站配置文件维护允许的节点 host/port；网页节点配置不能扩展该部署白名单。

禁用重定向和环境代理；验证证书及主机名。解析全部 IPv4/IPv6 地址并在实际建立连接时复核，阻止回环、私网、链路本地、云元数据、未指定、多播及其他非公开地址；任一解析地址不合格则拒绝。固定允许 host 也不能跳过 IP 检查。首版不支持生产内网节点例外，后续内网方案单独评审。

客户端设置连接/请求超时和响应大小上限，错误只暴露类别及操作编号，不包含请求头、远端原文或秘密。单节点失败不无限重试，也不阻塞其他车辆。测试通过专门注入的 transport 使用回环地址，生产配置不提供一键关闭防护的开关。

## 4. 内部身份与节点模式

A 为自身持久化 `main_instance_id`，为用户分配不可重用的 `subject_id`，关联现有 `users.id`。B 维护 `(main_instance_id, subject_id) -> B_user_id` 的唯一映射，并固定接受的主站/节点/车辆身份。A 与 B 不假定数字用户编号相同，也不按邮箱相同自动认领已有 B 用户。

节点成员预配必须在一个事务内完成内部用户和映射：

- 固定普通用户角色，初始余额为零，不触发默认订阅、注册/邀请赠送或充值流程。
- 使用无外部投递用途的内部地址和不可供用户登录的凭据；不复制 A 的邮箱登录身份或设置可由用户使用的密码。并发同主体预配只得到同一内部用户；响应丢失后按主体重试，不创建第二个账号。
- 不允许请求指定管理员角色、钱包余额、任意 B 用户编号或任意全局分组。内部成员设置 `RestrictPublicGroups=true`，只接受节点/车辆配置中允许的分组和服务策略；空分组也不能退回任意公开分组。
- 预配只是映射就绪，不能生成有效服务授权或 API Key。真正服务额度/订阅配置及计时由阶段 4 决定，拼车人民币金额不转换为 B 钱包充值。

新增节点 `authorization_mode=managed`，旧配置默认保留 `oidc`，二者显式互斥，不回退混用。在 managed 模式中：

- 普通成员不通过本地密码、OAuth、找回密码或用户会话登录 B；管理员恢复和管理登录保留。
- 模型 API Key 的使用权限由 B 本地的 managed 映射、成员授权、用户状态、服务时间及租约判断；沿用原分组、额度等校验，管理员模型 Key 不得到绕过门禁的特权。
- 不伪造 `auth_identities` 的 OIDC 记录。OIDC 配置约束仅应用于旧模式，managed 模式要求明确的主站及节点身份配置。
- 旧 OIDC 成员、CLI 和迁移记录不改写；模式切换不自动迁移老授权，冲突数据需要显式迁移方案。

## 5. 专用协议与接口复用

以下契约已在本地实现，B 的扩展统一放在 `/api/v1/admin/carpool-control/v1` 下，继承管理员认证、合规及审计；还要检查 managed 模式和固定目标身份：

| 命令 | 契约 |
| --- | --- |
| `GET /info` | 返回协议、能力、节点/车辆/主站和节点实例编号，不返回秘密 |
| `PUT /members/:subject` | 幂等预配内部用户，返回稳定映射；不授予服务 |
| `PUT /members/:subject/grant` | 应用有版本的 `prepared / active / paused / revoked` 授权 |
| `POST /members/:subject/keys` | 归属校验后创建 Key，要求幂等键；仅 active 且服务已开通可执行 |
| `PATCH /members/:subject/keys/:id` | 更新名称或启停，验证 Key 的 owner 与 subject 一致 |
| `DELETE /members/:subject/keys/:id` | 幂等删除本人的 Key，停用后仍可执行，不恢复授权 |

无「指定任意用户后模拟登录」接口，也不把节点管理员 API Key 当作普通用户 JWT。B 的这些扩展需要我们维护的节点构建；原版 B 可有普通管理 API，但缺少本协议时必须标为不兼容，不能假装已经开通。

A 对普通用户只开放车辆范围的 `/api/v1/carpool/cars/:id/keys`、`/keys/:key_id`、`/usage`、`/usage/stats`。每次都从登录身份和车辆成员记录计算节点、subject、B 用户编号；用户不能提供 node URL、B 用户编号或调用任意远端路径。

读取已有 Key 和用量优先复用上游管理接口。A 仅允许固定查询字段、限定日期区间及每页最多 100 条，强制覆盖所有用户过滤条件。返回 DTO 使用白名单：本人 Key 元信息、时间、模型、tokens、用量/费用统计等；不原样透传管理员响应，不返回上游账号、管理员信息、其他用户、内部错误原文或请求/对话正文。

首版 Key 创建只开放名称，绑定该车确定的分组及有效期；不开放用户自定义 Key、任意分组切换或提高车队权限。列表默认掩码显示，完整 Key 仅在创建成功或同一创建请求的合法恢复中返回。明确提供删除/重建路径，不默默增加永久明文展示功能。

### 幂等与敏感响应

- A 持久化创建操作编号、操作者、车辆/subject、规范化请求摘要和下游 Key 编号，不保存明文 Key；下游操作编号保持稳定，不随浏览器重试轮换。
- B 将命令登记与 Key 创建原子提交；同键同请求返回同一资源，不重复创建。命令记录保存 Key ID 和摘要，不另存明文响应；合法重放再从原 Key 读取。已删除的 Key 返回终止状态，不重建。
- 重放前再次验证用户/归属/服务资格；被撤销者不得靠旧请求取回密钥。删除和暂停不因幂等重放而恢复。
- A 不使用会保存完整响应的通用幂等包装器处理明文 Key。日志、追踪、审计和错误正文均省略凭据；客户端不将完整 Key 存入 localStorage 或恢复日志。
- A 尚未收到 B 的结果不等于失败；保留原请求核对，不能显示一个实际上没有在 B 创建成功的本地 Key。

## 6. 授权同步、租约与失败恢复

本期采用 **A 主动下发 + A 持久化任务和每分钟对账**，不同时开发 B 反向拉取；这替代原路线图中的双向推拉方案，避免再给 B 配置访问 A 的管理凭证。B 在模型请求上只读本地授权，不逐次回源 A。

- 以主站用户/成员/服务授权记录为权威，不把连接 ready、预配成功或 B 普通用户 active 当作已开通。
- A 的成员授权版本单调递增；写入待同步状态和任务后才发送。B 拒绝旧版本覆盖和同版本异内容，同版本同内容幂等；节点目标或主站身份不符直接拒绝。
- 每份 active 租约最长 15 分钟且不得超过服务结束时间。B 用自身数据库时间验证，A/B 时钟漂移导致不合法租约时显示明确错误，不延长窗口绕过检查。
- 任务有可恢复的领取租约，多 worker 不能生成冲突版本；启动后继续未完成任务。可重试故障按 2/5/15/30/60 秒退避并加抖动，最多首次请求加 5 次自动重试，耗尽后等待管理员重试；周期对账每 60 秒运行。401/403/423、协议或目标不匹配直接转人工处理，不无限重试。
- 发送前重读最新授权，撤销/暂停优先，过时的 active 任务不继续发送。A 收到成功响应后只按匹配的操作/连接代次写回，迟到响应不能覆盖更新的撤销或凭证轮换。
- 拼车撤销/暂停持久化待同步任务；主站通用用户禁用/删除至少由周期对账检查，停止续租。网络正常时尽快撤销，网络故障不承诺即时撤权：旧权限最多持续到已签发租约或服务期限到期。
- B 收到撤销后新请求立即拒绝，包括预热缓存的旧 Key；已开始的流式响应允许完成，沿用阶段 0 的约定。

A 故障时不能创建/管理 Key 或查看实时记录；B 已持有的有效授权可以持续到租约结束，之后拒绝新模型请求。B 故障时 A 显示该节点不可用；不把查询失败显示为零用量，不转到另一车，不声称授权/密钥已经同步成功。首版不缓存完整用量明细或明文 Key。

## 7. 与阶段 4 的严格分界

阶段 3 实现连接、身份、协议、同步和页面能力，但正常业务只允许建立连接及 prepared 映射，不能通过「添加成员」「预配」「同步」自动写 active 服务授权。

阶段 4 才提供车辆开通事务：资源及服务策略检查、全员映射准备、共同服务起止时间、明确管理员确认、发布 active 授权及真实可用状态。阶段 3 的用户创建 Key 入口在未开通车辆上必须保持不可用，服务日期仍为空。

测试可以通过只存在于隔离测试 harness 的服务授权夹具验证 active、暂停、到期、撤销及模型调用；不得给生产编译加入隐藏开通接口、测试授权参数或绕过资格的环境开关。阶段 3 验收不等于阶段 4 交付。

开通后的退款政策不在本阶段扩展；当前仅有未开通退款流程。不能因为接入节点而把既有「未开通全额退款」接口套到已服务订单。

## 8. 拆分与验收

### 3A：节点连接与凭证管理

增量迁移、A 连接记录和严格网络客户端、加密凭证、连接检查、B 协议信息与模式配置。不预配成员，不发服务授权，不新增用户 Key。

验收：错误 Key、证书、目标、协议、解密失败、SSRF、重定向、DNS 换绑、混合 IPv4/IPv6、凭证换代和并发保存均明确拒绝；读回和日志不含秘密；禁用功能默认无新增入口。迁移重复执行不修改阶段 0/1/2 数据。

### 3B：内部成员、委托 Key 与授权同步

新增不依赖 OIDC 的映射与门禁、原子内部用户预配、专用 Key 命令、授权版本/租约、持久化任务与对账。复用现有管理查询及 APIKeyService 校验，不复制全套用户/计费逻辑。

验收：两个用户、两个节点、乱序和重复命令、提交后响应丢失、故障回滚、进程重启、旧 Key 缓存预热、暂停/服务到期/租约到期均有真实数据库与 HTTP 测试；不产生默认余额/订阅，不允许通过主站改变别人的 Key 或查询其他车辆用量。

### 3C：A 的统一页面与本机联调

管理员增加节点连接/状态及失败重试；「我的车」增加按车隔离的密钥与用量区域，展示节点 API 地址、连接错误和未开通状态。保留原 A 自有 Key/用量能力，不将其数据混为节点数据；不重做大厅布局。

验收：桌面/手机、中英文、加载/空态/权限/超时、明文 Key 生命周期与登出清理；本机 A/B/C 通过邮箱账号主站登录完成管理流程，不发成员 B 登录会话、不经 A 发送模型请求。旧 OIDC A/B 16 组、阶段 2 人工/测试订单流程仍需回归。

### 测试与发布边界

所有阶段先写失败测试再实现。真实 PostgreSQL 覆盖迁移、唯一约束、事务、并发、版本及任务恢复；伪造 HTTP 服务用于恶意节点/网络故障，不替代真实 B 的权限契约测试。后端 race/lint、前端全量测试/类型检查/构建和浏览器检查分别记录通过/失败/跳过。

本机实验仅虚构账号、局部生成的测试凭据及本地模型桩，不使用真实管理员 Key，不发送真实邮件，不购买资源，不部署生产。既有未提交改动保留，不擅自提交、重置、切换分支或推送。正式启用需完成凭证权限风险、备份/主密钥恢复、节点网络策略及阶段 4/5 的独立评审。
