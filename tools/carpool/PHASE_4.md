# 阶段 4：部署、开通与运行说明

本说明对应本仓库的定制版本。A、每辆车的 B 必须运行经过一起验证的兼容版本，不能用任意原版 sub2api 替代 B。当前工作区仍有未提交代码；本说明不表示镜像已发布，也不授权购买服务器、导入真实账号或部署生产。

## 版本与部署文件

复用 `deploy/docker-compose.local.yml`，叠加以下其中一个文件：

- A：`deploy/carpool/main.compose.yml`，配置参考 `main.env.example`。
- B：`deploy/carpool/node.compose.yml`，配置参考 `node.env.example`。

两台服务器各自保存数据目录、PostgreSQL、Redis、管理员账号和密钥。一辆车对应一个 B 数据库，不复用其他车的数据库或管理员 Key。模板没有向宿主机公开数据库/Redis 端口；示例将应用绑定到 `127.0.0.1:8080`，由宿主机 HTTPS 反向代理提供外部入口。

### 反向代理与真实客户端 IP

- 两套模板显式关闭 `SECURITY_TRUST_FORWARDED_IP_FOR_API_KEY_ACL` 旧版转发头兼容模式，并传入 `SERVER_TRUSTED_PROXIES`。后者是逗号分隔的实际代理对端 IP/CIDR，不是 JSON 数组；空值明确表示不信任任何代理，安全相关客户端 IP 此时会是直接对端地址。
- 使用反向代理时，根据应用容器实际看到的代理来源配置最小范围，例如确切地址的 `/32`，不要填写 `0.0.0.0/0` 或整个内网。宿主机反代经过 Docker 转发后，应用看到的可能是 Docker 网桥网关，不一定是 `127.0.0.1`，需要在实际部署中确认。
- 代理必须清洗客户端提供的转发头，按可信连接信息设置 `X-Real-IP`、`X-Forwarded-For`，并清除非受信来源的 `CF-Connecting-IP` 和自定义客户端 IP 头。仅覆盖 `X-Real-IP` 却透传其他伪造头不是完整的信任策略；使用 CDN 时还需验证其来源链路。
- 已有数据库中的运行时设置 `api_key_acl_trust_forwarded_ip` 可以覆盖启动配置。升级后须在管理端确认该兼容开关仍关闭，不能仅看到环境变量为 false 就认定已生效。
- 正式交付前，用自有测试请求携带伪造转发头，核对 IP ACL、会话和审计仍采用可信客户端地址，并验证公网不能绕过代理直接访问 8080。这项真实部署验收不由本地 Compose 解析测试替代。

模板要求显式提供 `CARPOOL_IMAGE`，不会默认使用上游 `latest`，但不校验镜像内容。应填写已验证定制镜像的不可变 image ID，或已拉取的 registry digest。`pull_policy: never` 防止启动时自动切换版本；目标服务器须先从受控渠道载入/拉取对应镜像。PostgreSQL/Redis 使用本地测试采用的版本标签，生产发布时也应记录其实际 digest。

构建命令供之后获准发布时使用，以下命令本身不等于已经执行：

```sh
docker build -f deploy/Dockerfile \
  --build-arg VERSION=carpool-phase4-local \
  --build-arg COMMIT=reviewed-working-tree \
  -t sub2api-carpool:phase4-local .
docker image inspect sub2api-carpool:phase4-local --format '{{.Id}}'
```

将实际输出的 `sha256:...` 填入 `CARPOOL_IMAGE`。跨服务器或 CPU 架构发布时要构建相应平台镜像，并分别记录其身份；不要把 macOS 测试二进制当作 Linux 镜像。当前功能含未跟踪文件，仅记录 Git HEAD 无法重现构建，需在后续获准发布时保存完整受审阅源码快照或提交版本。

## 配置 A

1. 在 A 的部署目录建立私有 `main.env`，按示例填入 HTTPS 公网地址、初始管理员账号、数据库密码和持久密钥。文件权限设为仅部署用户可读；不要提交、截图或贴到聊天。
2. `JWT_SECRET`、`TOTP_ENCRYPTION_KEY`、`CARPOOL_CONTROL_ENCRYPTION_KEY` 各自独立生成，A/B 也不能共用。JWT/TOTP 示例生成方式为 `openssl rand -hex 32`；拼车加密根为 `openssl rand -base64 32`。拼车加密根需要和数据库分别备份，不能随重启重新生成。
3. `CARPOOL_CONTROL_ALLOWED_ORIGINS` 填入本期会使用的 B 公网 HTTPS origin，多个用逗号分隔，包含非默认端口时必须完全匹配。新增 B 域名后先调整白名单并重新加载 A 配置。
4. 在 A 原生设置中配置 SMTP、开放注册及邮箱验证，实际邮件投递需在生产前另行验证。用户只在 A 注册、登录。

在仓库根目录验证最终配置，不启动任何服务，也不把展开后的秘密打印到日志：

```sh
docker compose --env-file /private/path/main.env \
  -f deploy/docker-compose.local.yml -f deploy/carpool/main.compose.yml config --quiet
```

部署操作应在另行获准且备份、TLS、域名均就绪后执行。同一组 `--env-file` 和 `-f` 参数后使用 `up -d`。默认数据路径沿用基础 Compose 文件所在的 `deploy/`；两台服务器不要意外指向同一挂载目录。模板并不配置 DNS、TLS 或独立公网出口。

A 开启人工入车，关闭测试订单。整车价默认人民币 1400 元，可在草稿配置；人均价按规定人数而不是已加入人数均分。已有收款、退款事实和历史价格不会被默认值追改。当前已发布车辆的改价不属于新开通流程。

## 满员后配置 B

1. 在 A 登记本车节点域名，从车辆连接信息中取得 A 实例 UUID、本车 UUID 和节点 UUID。必要时可由管理员读取 `GET /api/v1/admin/carpool/control` 获取 A 实例标识；不要自行生成替代这些值。
2. 自行准备本车专属服务器、域名、TLS 和独立出口，载入与 A 兼容的定制镜像。建立私有 `node.env`，填写三个 UUID 及本机自己的管理员、数据库和加密配置。
3. B 使用 `managed` 授权模式、标准运行模式、`CARPOOL_NODE_GROUP_ID=0`，不需要提前手动建分组，也不启用成员 OIDC 登录。B 不开放拼车大厅。
4. 用 node overlay 的同类 `config --quiet` 命令验证配置。实际启动后由管理员登录 B，自行阅读并决定是否接受原生管理端的合规声明，再通过 OAuth 授权本车上游账号。自动化测试不会代为接受声明。
5. 在 B 原生设置中生成管理员 API Key，把 B origin 和 Key 填入 **A 的本车连接配置**。不是把 B 的 Key 填成 A 自己的全局管理员 Key。保存、检查连接；A 会发现并固定 B 的实例身份。

生产控制连接要求公网 HTTPS。即使加入白名单，loopback、内网和元数据地址仍被拒绝，不存在用于生产放行这些地址的测试开关。B 更换数据库、域名或车辆归属不等于普通 Key 轮换，不能直接覆盖已固定的身份。

## 初始化和交付

1. 用户微信站外付款后，管理员核实收款，在 A 将已注册用户加入指定车。系统只登记人工收款事实，不代收、不校验微信转账、不自动退款；用户不能自助占位。
2. 满员且 B 连接可用后，在 A 选择本车 OAuth 账号，点击初始化。自动创建或初始化本车原生订阅组、账号组关联和内部成员；失败后可以重试，不能重复创建或悄悄续期。
3. 等全部成员准备完成，再明确确认开通。此时才写入共同服务起止时间并分配 B 原生订阅，入车、满员或检查连接本身不会启动服务。
4. 用户在 A「我的车」创建自己的 Key，默认属于本车组。按页面 API 地址配置客户端，模型请求直接访问 B；OpenAI 地址为对应节点的 `/v1`，Anthropic 使用节点 origin。
5. 不同步 A 的密码或密码哈希，不创建 B 的成员网页登录会话。B 内部普通用户用于原生订阅、Key 和用量归属，用户不需要知道其内部邮箱。

B 的全局管理员 Key 权限没有被 A 的界面白名单降级。必须保护 A 的数据库、加密根及管理权限，并根据实际运维条件限制 B 管理接口的网络访问；不能把管理员凭证暴露给乘客或浏览器。

## 周额度与重置

- 人均首周/确认新周期但暂无有效估算时为 `1800/N`，不是 `(1800-100)/N`。四人车为 450 美元/周。
- 有有效预计总费用 T 时，同一原生组的周限额更新为 `(T-100)/N`。四人车 T=2000 对应 475，而不是 500。
- B 每分钟检查账号周期，自动额度更新最多每小时一次；管理员手动同步可立即执行相同检查。只限制周额度，不新增日、月或五小时额度。
- 调额不清已用、不重建分组、不延长订阅。额度下降后是否能调用由 B 原生规则决定，A 不代理或暂停模型请求。
- 账号百分比、预计费用和重置时间来自 B 的账号数据；个人已用来自 B 原生订阅，逐条记录来自 B 原生使用记录。人民币售价和这些美元计费数值是不同概念。
- 不完整、过期或读取失败的数据不能当成零。OpenAI 需要完整周观测（百分比、重置时间、采样时间）；旧实例升级后须等真实完整采样，不能把旧共享时间戳当新数据。
- 自动换周和手动同步共用去重规则，只清周用量，保留历史与服务有效期。B 原生请求维护已经重置过的行不会再清一次；同周期重复点击不能任意清空本周消费。
- 七天周期的小幅时间校正允许五分钟偏差，这是保守的应用策略，不是上游保证。超出策略、来源不明确或显示构造的 0% 会保留旧值并显示同步异常，不猜测清零。
- 缓存刷新失败保持待同步状态，B 会重试。A 离线或刷新失败不会增加模型停流条件；已经交付的 B 仍按本地原生订阅、用户/Key 状态和额度审核。新的撤销操作必须成功送达 B 才会生效，断网时不能承诺即时撤销。

## 故障恢复与升级

- 先看 A 的连接/同步状态及 B 的数据采样、周期和缓存状态，区分“未开通”“节点不可达”“源数据过期”和“额度已用尽”。不要以重建用户/组或重置订阅替代诊断。
- 未收到确定结果时先查询状态，再重试原操作；首次开通的有效期固定，重试不是续费。
- 备份 A/B 各自的 PostgreSQL、应用数据目录、持久加密密钥和版本清单。保存 B 的上游 OAuth 凭据必须使用受控备份，不公开上传测试日志或配置。
- 轮换 B 管理员 Key 时通过 A 本车连接配置更新，保留正确代次和 origin；清空输入代表保留原 Key，不代表删除。更换 A 拼车加密根须先做明确的密文迁移。
- 升级先验证数据库备份可恢复，再在隔离环境跑定制迁移和回归。数据库迁移与旧程序未验证兼容时，不要仅回滚镜像；也不要编辑已应用的迁移文件来绕过校验。

## 本地验证入口

配置模板测试只解析 Compose，不启动容器、不使用真实凭证：

```sh
node --test tools/carpool/deployment-config.test.mjs
```

模型测试需当前嵌入前端的服务器和测试程序，见 `docs/carpool/PHASE_4D_PLAN.md`。完整本地结果以 `PHASE_4C_RESULTS.md`、之后的 `PHASE_4D_RESULTS.md` 为准，不能把本地模型桩当作真实 OAuth、SMTP 投递、生产 DNS/TLS 或固定公网出口的验收。

## 本地交互预览

先构建前端和本机测试二进制（Docker 交叉编译方式见 `PHASE_3C.md`），再运行：

```sh
CARPOOL_CONTROL_PREVIEW=1 CARPOOL_NATIVE_SUBSCRIPTIONS_BROWSER=1 \
CI=true GIN_MODE=release DOCKER_HOST=unix:///Users/cl/.docker/run/docker.sock \
/tmp/carpool-4d-bin/carpool-control.test \
  -test.v -test.run '^TestControlBrowserNative$' -test.timeout=9h
```

- 程序打印当次随机端口的管理员和成员入口；角色入口只建立本地合成账号会话，不含真实凭据。两种身份共用一个 origin，需要同时查看时使用不同浏览器配置。
- 预览包含已满员的四人车、两人车，以及加入一人的三人车，整车总价均为 1400 元。可以建车、按合成用户邮箱人工加人、登记收款/退出/退款，或为已配置的测试 B/C 选择合成 OAuth 账号、初始化并明确开通。
- 预览启动生产同步任务，无需手动调用测试 drain 接口。初始化后须等成员同步完成再确认开通，四人车的原生个人周额度为 450。
- 这不是完整运营环境：其他 sub2api 管理菜单并未全部接入；不发送邮件、不接受合规声明、不提供实际模型上游。显示的 `.invalid` API 地址不能用于真实客户端请求。合成账号采样随时间过期会如实显示不可用，不伪造为实时上游数据。
- 只监听本机回环地址，不要转发端口或输入真实管理员 Key。八小时后自动退出并清理自己的容器；提前结束可向该次测试程序 PID 发送 `SIGINT`（`kill -INT <PID>`）。不要清理其他项目容器。
- 预览日志、截图和数据都留在私有临时目录，端口/PID 及当次验证结果记录在 `PHASE_4D_RESULTS.md`。角色会话过期后可重新打开角色入口，不需要知道合成密码。
